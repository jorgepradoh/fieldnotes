## 1. Ground rules

### 1.1 What exists

Tauri 2 (Rust shell) + SvelteKit 2 / Svelte 5 (runes) + TypeScript strict. Commands: `npm run check`
(svelte-check, must stay 0 errors / 0 warnings), `npm test` (vitest, 492 tests), `npm run build`.
The README's "Writing a module" section is the module contract: a module is
`src/lib/modules/<id>/` (+ `index.ts` exporting a `ModuleDefinition`), registered in
`src/lib/modules/index.ts`; **modules never import each other** and talk through the typed event
bus (`src/lib/core/bus.svelte.ts`); shared services live in `src/lib/core`.

Existing modules: `search`, `reader`, `synthesis` (AI Brief), `library`, `annotations`, `queue`,
`notes`, `pomodoro`, `export`, `debug`. Starter layouts are in `src/lib/core/presets.ts` (unknown
module ids are skipped, so presets may name new modules early).

Persisted data (do not break; changes must be additive with tested migrations):

| File (key) | Owner | Format today |
|---|---|---|
| `layouts.json` (`layouts`) | `core/workspace.svelte.ts` | `{version:2, activeId, layouts:[{id,name,instances,updatedAt}]}` |
| `library.json` (`library`) | `core/library.svelte.ts` | `{version:1, entries:[{paper, addedAt:number}]}`; loader also reads the June build's bare `[{paper, savedAt:ISO}]` |
| IndexedDB (`blobs.ts`) | library | file bytes keyed by content hash |
| `ai.json` (`settings`) | `ai/settings.svelte.ts` | `{version:1, activeId, profiles:[ProviderProfile]}` (API keys live here only) |
| `annotations.json` (`annotations`) | `core/annotations.svelte.ts` | `Record<paper.id, markdown>` |
| `queue.json` (`queue`) | `core/queue.svelte.ts` | `[{paper, status:"to-read"|"reading"|"done", addedAt:ISO}]` |
| `settings.json` (`settings`) | `core/settings.svelte.ts` | `{vimMode?}` |
| `workspace.json` (`workspace`) | legacy | read once to migrate to layouts; never written |

Persistence goes through `core/storage.ts` (`loadJson` / `saveJson`: Tauri store files in the
app-data dir, `localStorage` fallback in a plain browser, writes serialised per file). The old
`queue`/`annotations`/`settings` stores still hand-roll this; new code uses `storage.ts`.
Assume `queue.json` and `annotations.json` may be empty or populated, and that `library.json` may be in either the
legacy bare-list format or v1: keep every format loading, and write correct, tested migrations (not elaborate
migration UI).

Paper ids are per source: `s2:<paperId>`, `oa:<W…>`, `arxiv:<id>`, `zotero:<key>`, `local:<hash>`,
BibTeX imports. The library recognises one paper under several ids with `paperKeys()` in
`sources/merge.ts` (DOI, arXiv id, normalised title) and `library.find(paper)`.

Tests: colocated `*.test.ts`; pure logic lives in plain `.ts` files so it can be unit-tested
(there are no component tests); stores are tested by mocking `./storage` (see `library.test.ts`);
DOM tests opt in with `// @vitest-environment happy-dom`; IndexedDB via `fake-indexeddb`;
network is stubbed with `vi.stubGlobal("fetch", …)`.

### 1.2 Guardrails

1. **Untrusted text only through the sanitising renderer.** `{@html}` exists in exactly one place,
   `components/Markdown.svelte`, fed by `core/markdown.ts`. Never add another sink; extend that
   pipeline (and its XSS tests) instead. LLM output, paper text, dropped files and notes are all
   untrusted.
2. **No new Rust, no new Tauri plugins, no `Cargo.*` or `tauri.conf.json` changes** in any cloud phase
   (P0a is the one deliberate, local exception). Everything here is doable in the webview with the existing plugins. If you think you need
   Rust, stop and ask. File access stays scoped: dialog + `saveTextFile`/`pickFiles` in
   `core/files.ts`; no custom path-reading commands.
3. **Secrets never leave the machine or ride in layouts.** API keys and emails live in `ai.json`
   or the credentials store (§2.2), never in module `settings`, exports or logs.
4. **Network only through `httpFetch` / `fetchWithRetry`** (`core/net.ts`). Hosts are covered by
   the existing `https://**` scope. Handle 429s with the existing retry and a human message.
5. **LLM calls only on an explicit user action**, never in the background; anything that sends a
   paper's full text off the device shows the provider and asks first (§2.6).
6. **Don't touch Tauri package versions.** npm `@tauri-apps/*` and the matching Rust crates must
   stay on the same minor (the P0 parity test enforces it). Don't `npm update` or `cargo update`.
7. **Additive, migrated, tested data changes.** Never drop unknown fields; migrations are pure
   functions with tests built from real-shaped fixtures (see the legacy-library tests).
8. UI text is English. Styling uses the existing CSS variables (`--surface`, `--accent`, …).

### 1.3 What a cloud session cannot do — plan around it

- **Cannot launch the Tauri shell** (no webkit2gtk) and cannot run `cargo check`. Don't edit
  Rust. List shell-only behaviour (native dialogs, file drops, IPC streaming, OS integration)
  under "Not verified" and put it in the manual test plan for Jorge.
- **Cannot reach the live paper APIs.** Use the committed fixtures (§2.7) and the verified shapes in
  Appendix A. Never invent a field; if a shape isn't in a fixture or Appendix A, say so.
- **Has no model key.** Test providers against mocked streams. Never claim a real model call was made.
- It **can** run `npm run check`, `npm test`, `npm run build`, and drive the app in a browser
  (`npm run dev` / `preview`) with the network mocked, as the v0.2 PR did.

## 2. Shared design (decided once, used by several phases)

### 2.1 Paper identity — the library entry is the record

Problem: `queue` and `annotations` key by the raw `paper.id`, so the same paper arriving as
`s2:…` from one source and `arxiv:…` from another gets separate notes and queue entries, while the
library already knows they are one paper. Every feature below adds per-paper state (status, tags,
notes, chat threads, highlights), so this is fixed first (P1).

Rule: **the library entry's `paper.id` is the record id.** All per-paper state is keyed by it.
A paper from anywhere (search result, connection, import) resolves to a record with
`library.find(paper)`; if there is none it has no per-paper state until it is saved.
P1 adds `library.idFor(paper): string | undefined` and `library.ensure(paper): string` (saves if
missing, returns the record id). Ids never change once an entry exists (`enrich` already keeps them).

### 2.2 Source credentials (introduced in P2)

Three phases need the same keys (Connections, What's New, Unpaywall). Add
`core/credentials.svelte.ts` backed by `sources.json` (via `storage.ts`): `{ semanticScholarKey,
openAlexKey, email }`, plus a small "Paper sources" section in `components/SettingsMenu.svelte`.
Search keeps its per-instance fields as **overrides** (effective value = instance setting ?? global),
so nothing existing breaks. The file is separate from layouts, so it can't be exported.

### 2.3 Getting a paper's PDF — `core/paperFiles.ts` (introduced in P3)

`getPaperPdf(paper, { signal }): Promise<{ bytes, origin: "library"|"remote"|"unpaywall" } | null>`:
library blob (via `library.find(paper)?.localFile`) → `paper.pdfUrl` through `fetchBytes` →
Unpaywall by DOI (needs the email). An in-memory LRU (≈3 files / 80 MB) so Reader and Chat don't
download twice. `Reader.svelte`'s `loadLocal`/`loadRemote` move onto it.

### 2.4 Bus events (add to `BusEvents`)

| Event | Payload | Emitted by → consumed by |
|---|---|---|
| `reader:goto` (P3) | `{ paperId: string, page: number, quote?: string }` | Chat / Annotations → Reader (opens that paper first if needed, scrolls to the page; P4 highlights `quote`) |
| `reader:selection` (P4) | `{ paperId, page, text }` | Reader → Chat |
| `chat:ask` (P4) | `{ paperId, text, quote? }` | Reader → Chat (prefills the input) |
| `search:run` (Q3) | `{ query: string }` | palette → Search |

Existing: `search:query`, `search:results`, `paper:selected`, `pomodoro:phase`, `app:error`.
Modules may import core stores (`library`, `watches`, …) directly; they never import each other.

### 2.5 LLM extension for documents (P3)

Keep `LlmProvider`/`createProvider` as the single seam (`src/lib/ai/`). Today `ChatMessage.content`
is a string and `LlmEvent` is `text | done`.

```ts
// ai/types.ts (additive)
export interface PaperDocument {
  title: string;
  pdf?: Uint8Array;     // native PDF input, for providers that read PDFs (Anthropic)
  pages?: string[];     // extracted text, index 0 = page 1, for text-only providers
}
export interface ChatRequest { /* existing */ document?: PaperDocument }
export interface Citation { page: number; endPage?: number; quote: string }
export interface AnswerSegment { text: string; citations: Citation[] }
export type LlmEvent =
  | /* existing text | done */
  | { type: "answer"; segments: AnswerSegment[] }   // once, just before `done`
// `done.usage` gains cacheReadTokens / cacheWriteTokens
export interface LlmProvider { /* existing */ countTokens?(req: ChatRequest): Promise<number | null> }
```

- **Anthropic** (`ai/anthropic.ts`): put the PDF in the first user message as a `document` block
  (`source: {type:"base64", media_type:"application/pdf"}`, `title`, `citations: {enabled:true}`,
  `cache_control: {type:"ephemeral"}`) followed by the question text. Because the API is stateless,
  **resend the identical document block in the first user message of every request**; the byte-identical
  prefix is what hits the prompt cache on follow-ups. Stream text as today, then build `answer`
  segments from `finalMessage().content`: text blocks carry `citations[]` of type `page_location`
  (`cited_text`, `start_page_number`, `end_page_number`, 1-indexed). Keep the existing refusal /
  server-side-fallback handling untouched. Citations are incompatible with structured outputs
  (`output_config.format`) — don't combine them. `countTokens` uses `messages.countTokens` with the
  same document block.
- **OpenAI-compatible** (`ai/openai.ts`): no PDF input; inject `pages` into the system prompt as
  `[p.1] … [p.2] …` inside an untrusted-data block (reuse the defanging in `ai/prompt.ts`), instruct the
  model to cite as `[p.N]`, and parse those markers into `Citation`s (no verbatim quote). Token
  estimate = `estimateTokens` (chars/4). Refuse to send (clear message, never silently truncate) if the
  estimate exceeds what the profile says it can take — add an optional `contextTokens` to the profile.
  `normalizeAiFile` rebuilds each profile field by field and **drops unknown fields**, so extend it (and its tests) for
  every new profile field (`contextTokens` here, `documentConsent` in §2.6).
- System prompt for chat: answer only from the document, say when it isn't there, cite pages, treat
  the document as untrusted data (it can contain instructions).

### 2.6 Cost and privacy UX (P3; reused by Synthesis)

- `ai/pricing.ts`: small dated table keyed by model-id pattern → per-MTok input / output / cache-read.
  Show **tokens always, dollars only when the model is in the table**, always labelled "estimate".
  Appendix A has the starting numbers (2026-09-25); prices go stale, so the table carries its date.
- Before the first message of a thread that sends a document: "~38k tokens (≈ $0.15 now, ≈ $0.02 per
  follow-up while cached)". After each turn show real `usage` including cache reads.
- `ai/profiles.ts` gets `isLocalProfile(profile)` (host is localhost/127.0.0.1/::1; extract the ad-hoc
  regex from `Synthesis.svelte`). Badge: **"Stays on this computer"** vs **"Sends the full text to
  <host>"**. First document send per profile asks for consent (stored on the profile in `ai.json` as
  `documentConsent`; see the `normalizeAiFile` note in §2.5).
- The profile editor currently lives inside `Synthesis.svelte` (settings view). Extract it, unchanged,
  into `components/AiSettingsPanel.svelte` and use it from both Synthesis and Chat. No behaviour change.

### 2.7 Fixtures (local prep steps F1 and F2)

The cloud sandbox can't reach the APIs, so **real responses are captured by a local session and committed to `main`
before the phase that needs them** (F1 before P2, F2 before P3), in `src/lib/sources/__fixtures__/`, together with a
`scripts/capture-fixtures.mjs` so they can be refreshed. They are committed to a public repo, so **capture them for
well-known public papers, never from anyone's personal library**:

- F1 — S2: `references`, `citations`, `recommendations?from=all-cs` and paper-by-`ARXIV:` for a famous arXiv paper
  (e.g. `ARXIV:1706.03762`); OpenAlex: work-by-DOI for a published paper with a reference list (e.g. `10.1038/nature14539`
  with `referenced_works`, `related_works`, `is_retracted`), a `cites:` page, an `openalex:W1|W2|W3` batch, a known
  retracted work (`10.1016/s0140-6736(97)11096-0`), and a recent arXiv preprint that OpenAlex resolves with
  `referenced_works_count: 0` (to pin that behaviour); arXiv `id_list` Atom.
- F2 — Unpaywall for one open-access and one closed DOI. Unpaywall requires a contact email on every request: use one the
  maintainer explicitly chooses for this, and do not commit it.

Trim lists to ≤ 3 items. Tests import the fixtures; **do not hand-write API JSON from memory.**

### P1 — One record per paper

**Goal.** The library is the only paper store; status, tags and notes live on the entry; Queue and
Annotations become views over it.

**Data (library.json v2, additive).**

```ts
type PaperStatus = "to-read" | "reading" | "done";
interface LibraryEntry {
  paper: Paper; addedAt: number;
  status?: PaperStatus; statusAt?: number;   // replaces queue.json
  tags?: string[];                            // trimmed, lowercase, unique
  note?: string;                              // markdown; replaces annotations.json
}
interface LibraryFile { version: 2; entries: LibraryEntry[]; orphanNotes?: Record<string,string>; migrated?: {queue?: true; annotations?: true} }
```

The loader accepts the legacy bare list, v1 and v2; it writes v2. Unknown fields are preserved.

**API on `LibraryState`.** `idFor(paper)`, `ensure(paper)`, `setStatus(id, status | null)`, `setNote(id, text)`,
`addTag/removeTag(id, tag)`, selectors `byStatus(status)` and `tags()` (name + count, sorted). All writes go
through the existing batched `persist()`.

**Migrations (once, on first load when the old files exist and `migrated.*` is unset; never delete the old files).**
- `queue.json`: for each entry oldest first → `addMany([paper])`, then set `status`/`statusAt` on the resulting
  record (keep an existing status if the entry already has one).
- `annotations.json`: for each `id → text`: if a record with that id exists set `note`; otherwise keep it in
  `orphanNotes` and adopt it when a paper with that id is later added. **Never drop a note.**
  (Correctness and tests matter; elaborate migration UI doesn't.)

**Modules (ids unchanged so saved layouts still load).**
- **Queue:** columns from `library.byStatus`; "+ Queue" = `library.ensure(paper)` then status `to-read`
  (documented behaviour change: queueing also saves to the library); "Done →" at done **clears the status**
  (the paper stays in the library). Extract the column/advance logic into a pure `library/queue.ts` with tests.
- **Annotations:** reads/writes `entry.note`; for a paper that isn't saved, show "Save to library to add notes"
  with a button (no silent saves). Preview already goes through `<Markdown>`.
- **Library:** status chip, inline tag add/remove, filter by status and tag (extend `library/query.ts`).
- **Export:** BibTeX gets `keywords` (tags); Markdown gets Status / Tags / Notes; JSON gets `status`, `tags`,
  `note` and keeps the existing `annotation` field (= `note`) and `savedAt`. Update `exporters.ts` and its tests.
- **Reader / Synthesis / importer:** switch to `library.find/idFor`; no behaviour change.
- Delete `core/queue.svelte.ts` and `core/annotations.svelte.ts` after the modules move; keep the legacy
  readers inside the migration code. `+page.svelte` stops loading them.

**Tests.** v1→v2, bare-list→v2, queue/annotations migrations (duplicates, orphan notes, repeat run is a
no-op, partial/corrupt old files), selectors, identity (`ensure` for the same paper under another source id
returns the existing id), export formats, queue view logic.

**Done when** the same paper reached from two sources shows one status/notes/tags everywhere, and a v1 library
and the legacy bare-list fixture load unchanged and upgrade on first write.

**Needs Jorge.** Open the app on the real data; queue a paper from Search; re-find it via another source and
confirm one entry; export all three formats.

### P2 — Connections (+ lookup, omnibox, retraction flags)

**Goal.** Select a paper → see what it cites, who cites it, what's similar; one click to save/queue/follow.

**Shared pieces first.**
- `core/credentials.svelte.ts` + Settings section (§2.2).
- `PaperSource.lookup?(id, opts): Promise<Paper | null>` (additive). S2: `GET /graph/v1/paper/{id}?fields=…`;
  OpenAlex: DOI path form; arXiv: `id_list`. `sources/lookup.ts`: pure `parseIdentifier(text)` →
  `{kind:"doi"|"arxiv"|"s2"|"openalex"|"url", value}` (accepts DOIs, arXiv ids and URLs, `doi.org`, `arxiv.org/abs|pdf`,
  `semanticscholar.org/paper/…`, `openalex.org/W…`) and `lookupPaper(text)` that tries sources and merges with
  `mergePapers`.
- Fix the S2 mapper: `openAccessPdf.url` can be `""` (verified live) → `||` not `??`, so it becomes `null`.
- `Paper.retracted?: boolean` (optional): add `is_retracted` to OpenAlex `SELECT`/mapping, OR it in
  `mergePapers`, show a "RETRACTED" badge in Search rows, Reader header and Library rows. OpenAlex also prefixes
  titles with "RETRACTED:"; don't parse that.

**`sources/connections.ts`.** `getConnections(paper, kind: "references"|"citedBy"|"similar", { offset, signal })` →
`{ rows: {paper, influential?}[], total?, next: number|null, provider: "semantic-scholar"|"openalex" }`.
- Provider order: **Semantic Scholar first** (accepts S2 id, `ARXIV:`, `DOI:`; has `isInfluential`), **OpenAlex as
  fallback**. Resolve the seed id in this order: `s2:` id → DOI → arXiv id → (OpenAlex only) `oa:` id → title match.
  **Measured (Oct 2026) on a sample of 8 recent arXiv preprints:** OpenAlex resolved 7 by arXiv DOI, **every one with
  `referenced_works_count = 0`**; S2 returned 34–88 references for each of 4 of them, including the one OpenAlex couldn't
  find. So in this sample OpenAlex is no fallback for preprints (recent preprints may simply lag in its reference
  ingestion; the rule below holds either way), while it is a real one for *published* papers (Crossref-backed: 54
  references on a Nature paper). Fall back to OpenAlex only when its record has `referenced_works_count > 0`; otherwise
  show "No reference list for this preprint from OpenAlex" instead of an empty list. Many libraries here are mostly

## Appendix A — verified API facts

*Checked live on 2026-10-04 unless marked otherwise. Treat fixtures (§2.7) as the source of truth once they exist.*

**Semantic Scholar** (`https://api.semanticscholar.org`)
- `GET /graph/v1/paper/{id}/references?fields=…&limit=&offset=` → `{offset, next?, data:[{citedPaper:{paperId, externalIds, title,
  year, citationCount, openAccessPdf, authors:[{authorId,name}]}}], citingPaperInfo:{…}}`.
- `GET /graph/v1/paper/{id}/citations?…` → `data:[{isInfluential:boolean, intents:string[], citingPaper:{…}}]`.
- `{id}` forms verified: S2 paperId and `ARXIV:1706.03762`; `DOI:10.…` is documented but not exercised.
- `GET /recommendations/v1/papers/forpaper/{id}?fields=…&limit=&from=all-cs|recent` → `{recommendedPapers:[…]}`. Default `recent`
  returned `[]` for a 2017 paper; `from=all-cs` returned results.
- Gotchas: `openAccessPdf` is `{url:"", status:…}` when there is none (empty string, not null). Shared pool: **429 occurred**.
  Key via `x-api-key`. `POST /graph/v1/paper/batch` exists (429'd during planning; shape unverified).

**OpenAlex** (`https://api.openalex.org`)
- `GET /works/doi:{doi}?select=…` works for indexed DOIs (lower-case). arXiv DOIs (`10.48550/arxiv.<id>`) resolved for
  7 of 8 sampled recent preprints **but with `referenced_works_count: 0` on all seven**; a famous 2017 arXiv paper
  (`…arxiv.1706.03762`) returned no work (404 on the path form, empty on `filter=doi:` and on
  `filter=locations.landing_page_url:https://arxiv.org/abs/…`). For comparison S2 returned 34–88 references for four of them.
- Fields: `referenced_works[]` (full URLs), `referenced_works_count`, `related_works[]` (URLs), `is_retracted` (verified `true`
  for a known retracted paper; its title is prefixed "RETRACTED:"), `open_access{is_oa,oa_status,oa_url}`,
  `best_oa_location{pdf_url|null, landing_page_url, version, license}` (`pdf_url` can be null while `is_oa` is true), `cited_by_api_url`.
- Cited-by: `GET /works?filter=cites:W…&per-page=&page=` → `meta.count`. Batch hydrate: `GET /works?filter=openalex:W1|W2|W3`
  (verified with 3 ids; keep ≤ 50). Polite pool: `mailto=`.

**Unpaywall** — *not verified live (needs a contact email; none was sent).* Documented: `GET https://api.unpaywall.org/v2/{doi}?email=…` →
`{is_oa, oa_status, best_oa_location:{url_for_pdf, url_for_landing_page, version, license, host_type}, oa_locations:[…]}`. Capture a
fixture before implementing P3.

**Anthropic Messages API** (from the `claude-api` skill, cached 2026-09-25, and the installed `@anthropic-ai/sdk` 0.131.0 types)
- PDF input: `{type:"document", source:{type:"base64", media_type:"application/pdf", data}, title?, citations:{enabled:true},
  cache_control:{type:"ephemeral", ttl?:"5m"|"1h"}}` in user content, before the text block. Limits: 32 MB request, 600 pages
  (100 for 200K-context models). SDK types present: `DocumentBlockParam`, `Base64PDFSource`, `CitationsConfigParam`,
  `CitationPageLocation {type:"page_location", cited_text, document_index, document_title, start_page_number, end_page_number, file_id}`,
  `CitationsDelta`, `CacheControlEphemeral`, `MessageCountTokensParams`, `Usage.cache_creation_input_tokens/cache_read_input_tokens`.
  Citations come as `citations_delta` events and on the final message's text blocks — read the final message.
  Citations can't be combined with `output_config.format`.
- Models/prices per MTok (input / output; cache read): Opus 5.5 `claude-opus-5-5` $4 / $20; $0.20 · Sonnet 5.5 `claude-sonnet-5-5`
  $2 / $10; $0.20 · Haiku 4.5 `claude-haiku-4-5` $1 / $5 · Fable 5.1 `claude-fable-5-1` $10 / $50. The app's default profile is
  `claude-opus-5-5`; its provider deliberately sends no thinking/effort/sampling params — keep it that way. Cache writes cost
  about 1.25× input for the 5-minute TTL (check the docs for 1h). Prices change: the app treats them as estimates.
